## 0. 项目核心定位与目标

### 0.1 项目定义

开发一款**跨平台、轻量级桌面 GUI SSH 远程代码编辑器**，用于完全替代 VSCode Remote-SSH，
专门适配嵌入式弱性能 ARM Linux 板卡开发场景（RK3566 / RK3588 / 香橙派等）。

### 0.2 核心设计理念

**本地重计算、远程零负载**

- 所有 GUI 渲染、代码编辑、语法高亮、Git Diff 解析、文件缓存均在本地 PC 完成；
- 远程嵌入式板卡仅保留系统原生 SSH、SFTP、Git 基础能力，**禁止运行任何本项目常驻服务、代理、语言服务**。

### 0.3 核心架构链路

本地 PC（GUI 编辑器 / 语法解析 / Git 处理 / 缓存 / SSH 客户端） ← SSH/SFTP 协议 → 远程 ARM 板卡（原生 sshd、sftp、Git 仓库、源码文件）

### 0.4 版本定位（V1.0 非 IDE）

本版本仅聚焦**远程代码浏览、编辑、保存、语法高亮、Git 行级差异标记**，不做全功能 IDE，严控开发复杂度。

### 1.1 客户端形态：纯桌面 GUI 应用

必须为标准 Desktop GUI 桌面程序：支持全鼠标可视化操作；非 Web IDE、非浏览器应用、
非 VSCode 插件、非纯终端程序、非 Vim/Neovim 工具。

### 1.2 跨平台兼容要求

必须同时适配两大主流平台，支持免环境安装运行：

- Windows：适配 Win10/Win11，打包为 `RemoteCodeEditor.exe` 可执行文件；
- Ubuntu：适配 22.04+，优先打包为 `RemoteCodeEditor.AppImage`，可选 `.deb` 安装包。

用户运行要求：无需安装 Python、无需配置依赖，双击即可启动。

### 1.3 远端零负载硬性约束

远程 ARM 板卡**禁止运行**任何重型常驻服务：

- 禁止：VSCode Server、Remote Agent、LSP 语言服务、索引服务、Node.js 常驻服务、本项目自定义后台服务；
- 远端仅需系统原生能力：sshd、sftp、Git、标准 Linux 文件系统。

### 1.4 V1.0 功能边界（明确非目标）

第一版本**不实现**以下功能：LSP 代码补全 / 智能提示 / 语义分析、代码调试 / 编译 / 运行系统、
Docker 集成、远程项目索引、插件系统、AI 助手、全量 IDE 工作区能力。

> 例外（用户明确要求，见 [devlog.md](devlog.md) §13）：**集成终端**已加入（§5.17）。
> 它只是「在既有 SSH 连接上开一条 shell 通道」，不引入远端常驻服务，也不改变 H3 与 H1
> 的定位 —— 编辑器本身仍然是 GUI 程序，终端只是底部面板里的一个可选工具。

## 2. 典型使用场景

1. 开发者使用 Windows / Ubuntu 本地电脑，启动桌面客户端；
2. 选择 / 新增 ARM 板卡 SSH 连接（RK3566/RK3588/香橙派等嵌入式 Linux 设备）；
3. 连接成功后，在远端**选择要打开的文件夹**（默认定位家目录，按主机记住，下次自动打开）；
4. 可视化浏览远程板卡代码目录，打开源码文件，本地实时编辑渲染；
5. `Ctrl+S` 保存，通过 SFTP 上传覆盖远程文件；
6. 编辑器左侧行号区域实时彩色标记当前文件相对于 Git 仓库 `HEAD` 的改动（新增 / 修改 / 删除）。

## 3. 整体系统架构

本轮版本要求「前后端解耦、模块化分层」：GUI 与网络、Git、文件逻辑完全隔离，
UI 层不得内联网络 / Git / 文件系统逻辑。分层结构、链路图与实际目录见 [design.md](design.md) §1、§3。

## 4. 技术选型规范

### 4.1 核心技术栈（优先）

Python + PySide6/Qt。

### 4.2 选型理由

- 完美支持 Windows / Linux 跨平台 GUI 开发；
- 组件成熟（文件树、多标签、Dock 窗口、右键菜单）；
- SSH/SFTP、文件处理、Git 解析生态完善；
- 支持 PyInstaller 一键打包独立可执行程序。

### 4.3 选型优先级

稳定性 > 开发效率 > 跨平台兼容性 > 性能 > 扩展性 > 技术新颖度。

备注：若当前组件存在致命问题，可替换合理跨平台方案，禁止为炫技增加复杂度。
（与 Rust/egui、Rust/Tauri、C++/Qt 的逐项取舍见 [design.md](design.md) §2。）

## 5. 核心功能详细需求

### 5.1 SSH 远程连接能力

#### 5.1.1 连接参数

支持 Host/IP、端口、用户名、密码、SSH 私钥、私钥口令；两种认证方式（密码 / 私钥）。

#### 5.1.2 核心能力

- 多主机保存管理、快速连接、断线自动重连；
- 连接超时、认证失败、网络异常等清晰文字报错；
- **不依赖系统 OpenSSH 命令行**，纯代码封装 SSH/SFTP 逻辑；
- 模块独立封装，与 UI 解耦。

### 5.2 SSH 主机管理

可视化主机管理面板，支持新增、编辑、删除、快速连接设备。

单主机配置项：设备名称、IP/域名、端口、用户名、认证方式、私钥路径、远程工作目录（可选默认值）。

实现补充：私钥下拉框直接列出**本机 `~/.ssh`** 中的可用私钥（无需从文件对话框里翻找）；
支持一键导入本机 `~/.ssh/config` 中已配置的 Host。

安全规范：密码禁止明文存储，第一版支持临时输入密码，后续可对接系统安全存储。

### 5.3 远程文件浏览

可视化远程文件树，支持目录展开 / 收起、文件预览打开。

右键菜单功能：新建文件 / 文件夹、删除、重命名、刷新目录、查看基础文件信息。

实现补充：连接成功后由用户选择工作目录（等同 VSCode 的「打开文件夹」），
支持随时切换；`~` 与相对路径按远端家目录展开。

实现补充：文件树按 Git 状态着色（未变更不着色，新增 / 修改 / 删除各一种颜色，
与 VSCode 资源管理器一致）；列宽优先保证文件名称完整可读，大小 / 修改时间作为
次要信息，面板过窄时自动让位。

### 5.4 文件编辑与同步机制（核心）

采用**本地缓存编辑、保存后上传**机制，杜绝实时高频 SSH 请求：

1. 打开文件：SFTP 下载远程文件至本地内存 / 临时缓存；
2. 编辑过程：纯本地操作，无网络请求，零延迟；
3. 保存文件：`Ctrl+S` 触发 SFTP 上传，覆盖远程文件。

优势：适配弱网络、避免编辑卡顿、降低板卡与网络开销。

### 5.5 基础编辑器能力

必备基础功能：行号显示、当前行高亮、自动缩进、Tab/空格适配、撤销/重做、全量快捷键、
复制粘贴、搜索替换、多标签页、未保存状态标记、鼠标精准选中滚动。

### 5.6 语法高亮

V1.0 必支持：C、C++、Python、Bash、YAML、JSON、XML、Markdown、CMake。

架构要求：高亮规则可扩展，后续可新增文件类型，无需重构核心逻辑。

约束：仅做语法高亮，不实现任何 LSP 语义解析。

### 5.7 Git 行级差异标记（核心核心功能）

#### 5.7.1 标记规则

编辑器左侧 Gutter 行号区域彩色标记，对标 VSCode 效果：

- 新增行：绿色标记；修改行：黄色/橙色标记；删除行：红色标记；
- 颜色配置集中管理，可自定义主题，禁止硬编码。

#### 5.7.2 Diff 对比基准

默认对比：当前远程文件工作区 & Git `HEAD` 基准版本。

#### 5.7.3 特殊场景适配

文件删除行识别：已删除的不存在行，仍在对应行号位置显示删除标记，提示用户变更。

#### 5.7.4 Diff 获取逻辑

- 通过 SSH 远程执行轻量化 Git 原生命令（`git diff`、`git status` 等）；
- Diff 文本传回本地，由本地程序解析渲染标记；
- 禁止远端搭建 Git 服务、禁止全量拉取仓库、禁止常驻 Git 进程。

#### 5.7.5 刷新策略

- 打开文件时：一次性获取 Diff 数据渲染初始标记；
- 编辑过程：仅本地标记脏状态，不频繁请求远端 Git 接口；
- 保存文件后：按需延迟刷新 Diff；
- 提供手动刷新 Git 按钮，保证稳定性优先。

### 5.8 Git 仓库识别

打开远程目录自动判断是否为 Git 仓库：非仓库时状态栏提示「Git: Not a repository」；
正常仓库显示当前分支与文件变更状态。

### 5.9 本地缓存机制

可缓存：SSH 主机配置、最近打开文件、编辑器状态、Git Diff 临时数据。

核心约束：**远程文件为唯一真实数据源**，缓存仅做体验优化，不替代远端数据。

### 5.10 文件冲突处理（重要）

场景：本地编辑未保存，远程文件被外部修改。

触发保存时弹窗提示，提供三选项：重新加载远程文件、覆盖远程文件、取消保存。

禁止静默覆盖远端文件，避免代码丢失。

### 5.11 文件编码兼容

默认支持 UTF-8、UTF-8 BOM、ASCII 编码；未知编码时弹窗提示用户手动选择，避免程序崩溃。

### 5.12 大文件与 UI 性能优化

支持 MB 级文件正常加载编辑；文件下载、解析、渲染全部异步处理，
禁止阻塞 GUI 主线程，杜绝窗口卡死、无响应问题。

### 5.13 异步线程规范

以下操作必须异步子线程执行，不阻塞 UI：SSH 连接、SFTP 上传下载、远端 Git 命令查询、
目录列表获取、文件解析。

### 5.14 异常容错

全面适配超时、连接拒绝、断连、权限不足、文件不存在等异常场景，弹窗友好提示，
程序不崩溃、不闪退。

### 5.15 状态栏与设置

状态栏展示：连接状态、当前工作目录、Git 分支、文件类型、编码、保存状态。

基础设置：主题、字体大小、缩进尺寸、自动保存、SSH 基础配置、编辑器配置。

### 5.16 日志与安全规范

- 本地日志目录记录连接、传输、Git 操作、异常报错；
- 严格脱敏：日志禁止打印、记录密码、私钥明文内容。

### 5.17 集成终端（用户追加需求）

- 在**已连接的 SSH 会话**上打开交互式 shell（sshd 自带的 shell 通道 + PTY），
  远端不部署任何常驻服务（满足 H3）；
- 底部面板多页签（对齐 VSCode Panel）：`Ctrl+`` / `Ctrl+J` 开关、`Ctrl+Shift+`` 新建、
  页签可关闭；面板正文区随窗口缩放，并**把窗口大小同步给远端 PTY**（`htop` / `vim` 全屏正常）；
- 渲染要求「强渲染能力」：自绘字符网格，有显卡时走 OpenGL（`QOpenGLWidget`）合成，
  无 OpenGL / 离屏环境自动退回软渲染，两条路径共用同一份绘制实现；
- 终端能力基线：16 / 256 色与真彩、加粗 / 暗淡 / 斜体 / 下划线 / 反显、光标定位与擦除、
  滚动区域、备用屏幕（`vim` / `less`）、宽字符（中文）两格对齐、回滚缓冲区、
  框选复制 / 粘贴；远端输出按 UTF-8 增量解码，多字节字符被分片也不会乱码；
- 终端字号跟随「编辑器字号 × 全局缩放」，`Ctrl+=` / `Ctrl+-` / `Ctrl+0` 一并生效；
- 终端不得阻塞 UI 线程：通道读取在后台线程，数据经信号切回 GUI 线程。

## 6. 跨平台打包与交付

### 6.1 Windows 交付

PyInstaller 打包独立 exe 程序（免安装版），干净环境双击直接运行，无依赖、无需 Python 环境；
另提供 NSIS 安装包（安装版），写开始菜单 / 桌面快捷方式 / 卸载项。

### 6.2 Ubuntu 交付

优先打包 AppImage 可执行文件（免安装版），授权后直接运行，适配 Ubuntu 22.04+；
同时产出 deb 安装包（安装版），声明 Qt 运行期依赖，进应用菜单、可用 apt 卸载。

### 6.3 外观资源可替换（打包之后仍然有效）

打包形态为单文件，程序自带资源在运行期不可修改；因此**字体 / 配色主题 / 文件图标主题
必须支持用户在「用户配置目录」下自行新增**（`<配置目录>/{fonts,themes,icon-themes}`），
并且应用内要有一个能看见、能打开该目录的入口（设置 → 外观 → 资源目录）。
用户目录与内置同名时不覆盖内置资源。详见 [packaging.md](packaging.md)。

### 6.4 跨平台代码规范

- 核心业务代码全平台通用，仅系统特殊逻辑差异化处理；
- 使用 `pathlib` 处理本地路径，禁止硬编码 Windows/Linux 绝对路径；
- 配置文件、缓存目录、密钥路径做跨平台适配。

## 12. 核心产品原则（最终准则）

远端低负载 > 本地 GUI 流畅体验 > 纯 SSH/SFTP 协议通信 > 无远端代理服务 >
不做冗余 IDE 功能 > Git Diff 精准可用 > 双平台兼容 > 鼠标可视化操作 > 程序稳定性优先。
